The idea behind Spark-H3

MiniMax-H3 · adaptive block sparse attention
01 / Exact attention branch
Spark-Reblock

Consecutive video positions are not necessarily similar in attention space, especially in noisy denoising steps. Reblock partitions tokens by learned Q/K affinity so a fixed Top-K block budget captures more important attention interactions.

Original Q / K→Landmark tree→Coherent 64-token blocks→Top-K exact
02 / Compressed attention branch
Spark-Reweight

Skipping the other key blocks entirely would discard their attention mass. Spark-Reweight creates weighted K/V summaries for the unselected tail and corrects their softmax mass with a log-bias, instead of treating a simple block mean as exact.

Unselected K/V→Weighted summary→Log-mass correction→Merge output
Put together: Spark-H3 computes the most relevant blocks exactly and covers the rest using a cheaper corrected approximation. Conditioning text/video/audio K/V sinks remain exact. In the reference integration, tokens form 64-wide leaf blocks, typical Top-K video-block density is 10%, and dense warmup steps keep early evaluations exact.

Where this fits in one denoising step

Repeated work within DiT

New layer Q/K/V→Reblock*→Route / Reweight→Attention

Q/K representations change across layers and denoising evaluations. By default, eligible layers rebuild layouts. An implementation can reuse a layout across a small group of nearby layers; cross-step reuse is a separate hypothesis requiring validation.

*The Reblock reuse across layers slider below models how amortizing this work affects effective latency. Reusing a permutation does not reuse Q/K/V or exact Top-K routes.

Spark-H3 reblock reuse opportunities

Approximate sensitivity

How often must layouts be rebuilt?

Assume the reblock process takes the same cost per invocation. Increasing the number of layers sharing a permutation amortizes that cost but may affect block quality.

Reuse intervalReblock / layerSparse layerFull-run speedup

Layer reuse vs. cross-step reuse

Reusing layout across layers: skips some landmark and permutation construction. Must check Q/K feature changes; Top-K can still be recalculated.
Reusing layout across denoising steps: could save more setup work, but the feature structure changes with denoising. Needs dedicated correctness and visual-quality validation.
Important: A reused token permutation is not the same as reusing selected attention blocks or Q/K/V values.

Research interpretation

For GPU kernel and end-to-end profiling

Measure each overhead independently

Record baseline attention, sparse attention, reblocking, Top-K proxy + selection, layout copies and residual layer ops with GPU events. Avoid double counting asynchronous work.

T_new = T_other + T_sparse + T_reblock + T_route + T_layout

Compare end-to-end, not only kernel TFLOPS

Check realized layer and video speedups, selected-block recall / attention mass, and video quality. Higher sparse-kernel throughput can be offset by reblocking overhead or lower utilization.

S_full = T_baseline_full / T_optimized_full
Default example: Attention is 60% of layer time. A 5× attention-only speedup gives 1.92× ideal layer speedup. With 5 ms of overhead it becomes 1.75×; with dense warmup steps and fallback layers, full-run gains are smaller. These are illustrative values, not measured Spark-H3 throughput.
